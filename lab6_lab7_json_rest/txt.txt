 1. Умные указатели (Smart Pointers)
Определение: Объекты, которые ведут себя как указатели, но автоматически удаляют объект, на который указывают, когда он больше не нужен.

Почему используем:

❌ Raw pointers (T* ptr = new T()) требуют ручного вызова delete

❌ При исключении delete может не выполниться → утечка памяти

✅ Умные указатели вызывают delete автоматически в деструкторе

В вашем коде:

cpp
std::unique_ptr<ProductInterface> product = ProductFactory::create(obj);
// product удалится сам, когда выйдет из области видимости
🔒 2. RAII (Resource Acquisition Is Initialization)
Определение: Идиома C++, где ресурс (память, файл, соединение) захватывается в конструкторе и освобождается в деструкторе.

Почему используем:

Гарантирует освобождение ресурса даже при исключении

Не нужно вручную вызывать close(), delete

Код становится безопасным и понятным

В вашем коде:

cpp
class JsonFileReader {
    QFile m_file;
public:
    JsonFileReader(const QString& path) {
        m_file.open(path);      // ← ЗАХВАТ ресурса в конструкторе
    }
    ~JsonFileReader() {
        m_file.close();         // ← ОСВОБОЖДЕНИЕ в деструкторе
    }
};
🏭 3. Паттерн Фабрика (Factory Pattern)
Определение: Порождающий паттерн, который определяет интерфейс для создания объектов, но позволяет подклассам или специализированному классу решать, какой именно объект создавать.

Зачем нужен (проблема, которую решает):

text
❌ Без Фабрики:
if (тип == "A") { ProductA* p = new ProductA(); }
else if (тип == "B") { ProductB* p = new ProductB(); }
// При добавлении нового типа нужно менять ВСЕ места создания
text
✅ С Фабрикой:
auto product = ProductFactory::create(jsonObject);
// Всё! Фабрика сама решит, какой объект создать
// Новый тип = меняем только фабрику
В вашем коде:

cpp
class ProductFactory {
public:
    static std::unique_ptr<ProductInterface> create(const QJsonObject& obj) {
        // Фабрика сама решает, создать продукт или нет
        if (isFresh(obj)) {
            return std::make_unique<ProductImpl>(...);
        }
        return nullptr;  // Нет продукта - тоже решение!
    }
};
Плюсы:

Единое место создания объектов

Легко добавлять новые типы продуктов

Код не зависит от конкретных классов

🏛️ 4. Паттерн Фасад (Facade Pattern)
Определение: Структурный паттерн, который предоставляет простой интерфейс к сложной системе классов, скрывая её внутреннюю структуру и взаимодействия.

Зачем нужен (проблема, которую решает):

text
❌ Без Фасада (клиент должен знать ВСЁ):
QFile file("warehouse.json");
file.open();
QByteArray data = file.readAll();
QJsonDocument doc = QJsonDocument::fromJson(data);
QJsonArray arr = doc.array();
// ... 50 строк сложной логики ...
QFile out("variant.json");
out.write(...);
text
✅ С Фасадом (клиент знает ОДИН метод):
ProcessingResult result = JsonProcessorFacade::process("warehouse.json", "variant.json");
В вашем коде:

cpp
class JsonProcessorFacade {
public:
    static ProcessingResult process(const QString& input, const QString& output) {
        // Внутри скрыто всё:
        // - Чтение файла (RAII)
        // - Парсинг JSON
        // - Создание продуктов (Фабрика)
        // - Сохранение результата
        return result;
    }
};
Плюсы:

Клиенту не нужно знать внутреннее устройство

Упрощает тестирование (фасад можно замокать)

Скрывает сложность подсистемы

Изменение внутренней логики не влияет на клиента
